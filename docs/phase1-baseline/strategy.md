# 策略与范围

日期：2026-10-28。当前阶段是“输入快照→完整规划优化→受控执行”的最小基线，不是完整闭环重规划系统。

## 1. 已确认方向

- 保留现有 odom_hyx 定位、静态地图、感知栅格，以及 MPC 和速度执行链的上下文；不另建 SLAM、感知或导航框架。
- 从现有栅格地图话题生成障碍掩码，不直接订阅点云。每次显式目标请求固定一个完整环境快照，执行普通 A*、碰撞感知化简、QP 优化和检测迭代。
- 本阶段完成两种调试方式，并最终验证受控实机移动；不是只输出可视化路径就算完成。
- 当前四舵轮，未来四全向轮。首期复用现有二维 vx/vy 接口，但四舵轮的转向响应、方向切换及实际轮速分配仍属执行验收条件，不由几何路径保证。
- 已授权在新工作区副本补齐参考撤销、超时保持和必要执行边界，不覆盖外部 MPC，不重写其主模型。

## 2. 最小算法与复用方案

```text
/map + 当前costmap完整快照 → 统一占据、保守面积距离
显式目标 + 停稳后的TF起点 → 普通8邻域A*
 → 碰撞感知DP → 可见弦合并
 → 矩形走廊 + 段时间分配 → minimum-jerk QP
 → 有界细分检查 → 插点/收紧走廊 → 有限次重解
 → 最终曲线与发布折线检查 → 几何Path → 原MPC执行副本
```

技术基线采用本地 TDT 示例的五次多项式、三阶导数目标和 OSQP 走廊思路，不因类名 MinimumSnap 就宣称使用四阶 snap。原 ESDF/DynamicVoronoi 可复用基本距离查询；只修本次接入必须的坐标、保守距离、所有权和失败边界，不重构无关模块。

建议新包位于 `transplant_ws/src/tdt_path_planning/`。MPC 如需改动则复制到新工作区并记录来源；启动时检查包解析，不能同时运行旧规划发布者或两个 MPC。不复制完整导航工程，只按依赖引入必需组件。

## 3. 两种调试方式与执行开关

| 项目 | 固定数据离线调试 | ROS真实接口快照调试 |
| --- | --- | --- |
| 输入 | 保存的静态图、完整障碍栅格、起点/目标及参数 | 现有 /map、costmap、TF、/goal_pose |
| 实现 | 一个可重复调用的规划核心，离线入口装载固定输入 | ROS节点仅负责接收、快照、状态及输出，调用同一核心 |
| 算法 | 完整A*→化简→QP→检测 | 相同，不另写算法分支 |
| 主要排查 | 几何、净空、优化、迭代与失败复现 | 话题/QoS、原点、分辨率、TF、更新同步与状态 |
| 复现 | 同一输入重复运行 | 保存完整快照后转离线入口回放 |
| 默认输出 | 调试文件/话题，不接执行 | 独立调试话题，不默认驱动 |

ROS方式另有默认关闭的执行许可开关。经非驱动验收后显式打开，才向执行 `/sPath` 交付；这不是第三套规划算法。单独用静态底图可作为离线测试用例，但不是实机绕开感知的模式；实机必须有有效感知与停止保护。

## 4. 当前快照与重规划的界限

- 快照包含静态底图和当时感知障碍；“静态求解”表示求解期间环境固定，不表示忽略当前动态障碍。
- 新目标是一次显式请求。相同坐标重复发布不应自动形成循环规划；停止后重试通过显式重新提交/触发，不增加复杂调度器。
- 本阶段不实现 global_monitor 的周期、停滞或自动碰撞重规划；0.50 s/1.5 s 的旧参数不作为本基线搜索调度要求。
- 执行时继续接收最新栅格，只用于前视安全检查、失效保持和许可续期；发现危险先停，不自动绕行、不因障碍消失自动恢复旧路径。
- 后续扩展可在同一核心之外接入 global_monitor 调度、运动中换轨和动态预测，本阶段不提前搭建通用插件/调度框架。

## 5. 最小改动原则

必要修改限于新规划包、运行/测试入口、参数文件及新工作区执行副本的安全接缝。若旧 MPC 的末端索引、加速度限制或断联处理实际阻碍本次正确执行，先定向复现，再做局部修正；不借机改目标函数、优化器、底盘模型、区域管理或串口协议。代码无法确认的实车能力记为放行门槛，不靠改测试掩盖。

后续扩展：完整闭环重规划、minimum-snap、多后端、定时轨迹接口、运动预测、姿态多边形扫掠、自动脱困/换目标和高性能优化。旧测试、旧耗时不继承为新版本结论。

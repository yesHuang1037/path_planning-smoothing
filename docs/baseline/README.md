# 本地暂存基线（2026-10-25）

本目录固定当前 T02-A 交付及来源证据。按用户最新要求，**仅初始化本地仓库并暂存，不创建 commit、标签、远端或推送**。因此这仍是可变的候选基线，没有可引用的提交 SHA；暂存区不等于提交历史或异机备份。

## 内容

- `sources.json`：原导航、TDT、SLAM 的路径、HEAD、分支和当前工作树差异哈希及状态；仅引用外部仓库，不保证其所有未跟踪文件可重建。
- `planner-import.json` / `planner-current.json`：原始导入包与当前包的完整文件 SHA256、权限清单；原始包来自有修改的工作树，不是直接取导航 HEAD。
- `import-to-t02a.patch`：原始导入包到当前 T02-A 的差异，包含新增文件。补丁使用 `original/` / `current/` 中间目录，应用时用 `-p2`。
- `evidence/` / `evidence.json`：2026-10-24 已运行的精选构建、测试、消毒器、保护记录及观测数据的原样存档和哈希；不是本次重新测试结果。完整本地历史仍在未跟踪的 `artifacts/T02/`。

源码、地图、文档与验证脚本纳入暂存；build/install/log、缓存、可执行产物及独立的 TDT 仓库不纳入。已存在文件不删除，原导航、SLAM、TDT 不作修改。

## 验证与使用

在工作区根运行 `python3 scripts/verify_baseline.py`，校验规划包/证据清单，在临时目录反向应用补丁重建原始导入包，并逐字节核对暂存区与工作树。该脚本不运行构建、不启动 ROS、不修改当前源码或暂存区；后续源码变化后它应提示偏离固定基线，而不是自动刷新清单。

查看本次暂存：`git diff --cached --stat`、`git status --short`。现在没有 HEAD，`git show HEAD`、基于标签的 worktree 或回退均不可用；需另行获准创建首个 commit 后才能采用这些流程。不对当前目录使用 `reset --hard`、`clean` 或覆盖式恢复。

以后每个独立任务应分开记录变更与实际测试版本；旧日志不能自动证明新代码通过。不得静默移动已固定标签。远端及异机备份不属于本次操作。
